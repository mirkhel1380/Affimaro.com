# Customer account settings

Each primary customer role has a private settings path: `/workspace/settings`, `/partner/settings`, `/creator/settings`, `/agency/settings`. `/settings` resolves the signed-in customer. The existing separate owner settings remain under the owner host. Preview settings use `/preview/{role}/settings` and save fictional preferences only in that browser; no customer API is called in preview mode.

Settings cover display name; light/dark/device appearance; density and reduced motion; click-report timestamps, page size and campaign defaults; real pending partnership reminders in the portal; opt-in discovery privacy; existing verified password recovery; active Affimaro sessions; role-appropriate tools, billing/earnings; a scoped account JSON export; and the existing separately confirmed closure flow.

`account_preferences` stores a strict JSON preference schema, an increasing revision and updated time. All reads and writes derive identity from the authenticated request. The write endpoint applies the existing same-origin and approved-account checks, rejects unknown fields, and uses compare-and-swap revisions. Owner, closed and unapproved accounts cannot use customer settings. Preferences never grant roles or change financial state.

The appearance bootstrap stores only theme, density and reduced-motion choices in a device-local key. A signed-in portal loads the account's saved preference, allowing it to follow the user across devices. It also follows OS theme changes and changes from another tab. Account data and session credentials are never stored by this appearance mechanism. Browser-blocked storage falls back to usable defaults.

Click-report activity timestamps and page size use the saved preferences. Graph/day aggregation continues to use UTC calendar days. New partner campaign links prefill the saved source and medium. Existing signed store destinations and accounting rules are retained.

Signing out other devices removes only the caller's other application session rows. The current cookie hash must match the authenticated account's active non-recovery session before any deletion. The current session and every foreign account remain intact. App-local revocation does not call Supabase global sign-out or revoke external provider tokens. The existing bridge checks the local session row on each new request. Password changes continue through the existing verified-code flow.

Account exports contain the caller's display profile, preferences, submitted application and public channel evidence projection. They exclude session tokens, encryption material, payment credentials and owner review notes. Financial exports remain in the existing role-scoped reports. No real account, session, email, payment or closure is changed during automated tests.


## Compact account workspace (October 2026)

All four customer portals use a compact forest-green header: Overview, Discover, Manage and Reports; an Earnings/Payments menu; page search (Ctrl/Cmd K); current open-item summaries; support; and a profile menu. No role switching is introduced. The avatar menu offers account settings, user profile, Light/Dark/Device themes and sign-out. Counts are current pending/open statuses, not unread notifications or a bank balance. Notification preferences control application, invitation and payment summaries; no email digest is promised.

Settings open a grouped directory (General, Profile, Finance, Technical, Workspace), with a section rail for focused edits. A member's private personal profile is separate from their reviewed application and public discovery listing. `member_profiles` stores optional first/last name, job title and private phone contacts. An own-account JPEG avatar is capped at 45 KB after metadata stripping. Browser uploads are limited to 5 MB JPEG/PNG/WebP, cropped/resized locally; SVG and remote URLs are not accepted. Contact numbers do not count as verified MFA factors. Sign-in email remains read-only and changes use the support path.

Member details and photo mutations share a compare-and-swap revision. Profile/display-name writes are batched with a transition guard; concurrent saves and admission/closure changes cannot partially overwrite another update. The avatar endpoint accepts no target account ID. Only the authenticated approved customer can retrieve their image, with no-store, nosniff and private response headers. Settings snapshots and exports never include image bytes; header events carry only the display name and avatar version. The photo and contacts are not exposed to other partners or the customer-facing directory. Account closure deletes the private member profile.

The four default portal homes now show actual 7/30/90 UTC-day click/order trends, estimated commission separated by currency and precision, current approved partnerships and actionable tasks. This is not a withdrawable balance. Shopify source holds still suppress estimated commission using the existing accounting expression. The overview has no write side effects, external API calls or payment execution. Assets are limited to an account's own business program or its exact approved, active receiving partnership. Clients are private to the agency; content plans are private to the creator. Existing business configuration remains at `/workspace?tab=program`; the affiliate publishing profile has its own `/partner/profile` route.

Design references: the owner-supplied impact.com affiliate screenshots; impact's public partner dashboard guide and Awin/impact account/profile guidance reviewed during implementation. They inform navigation structure, not copied financial or verification functionality. Account-free previews label every metric and edit as fictional.
